## 왜 이 문제를 선택했는가 (밴드 예약 관리)
공연 전후로 반복되는 실무가 엑셀·메신저·구두 전달로 흩어져 있었다.

1. **예약/게스트**: 초대 명단이 파일에만 있고 현장 입장과 안 맞음  
2. **티켓·권한**: 입장 가능 여부 확인이 느림  
3. **셋리스트·공연진·이벤트**: 게스트·밴드원에게 보여줄 정보가 채널마다 다름  
4. **체크인**: 이름·전화로 본인 확인하고 대시보드로 안내할 도구 부재  

→ “밴드 **예약 + 공연 당일 운영**”을 하나의 웹으로 정의했다.

## 실제 문제로 어떻게 검증했는가
- 밴드 동아리 **운영진**으로서 공연 운영 Pain을 직접 체감
- 관리자 엑셀 업로드 → 게스트 로그인·체크인 플로우로 실사용 검증

## 솔루션
| 역할 | 기능 |
|------|------|
| 관리자 | 엑셀 업로드(이름·전화), 공연·셋리스트·공연진·이벤트·티켓 설정 |
| 게스트 | 이름+전화 로그인 → 티켓/셋리스트/공연진/이벤트 확인 |
| 시스템 | 보호 라우트, Auth/Data Context, 공연·밴드·공연장 페이지 |

확장: Firebase, Socket.io, QR 체크인.
